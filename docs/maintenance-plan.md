# 90-day maintenance plan

Dates use Asia/Shanghai. This is intended work, not completed outreach.

| Period | Target | Work |
| --- | --- | --- |
| Oct 31–Nov 29, 2026 | v0.1.1 on Nov 29 | Invite 3–5 developers to try synthetic versions of real configuration contracts; triage parser/validation feedback weekly. |
| Nov 30–Dec 29, 2026 | v0.2.0 on Dec 29 | Convert repeated, consented workflows to fixtures; prioritize clear diagnostics and format compatibility. |
| Dec 30, 2026–Jan 28, 2027 | v0.2.1 on Jan 28 | Review packaging, constraints and privacy tests; publish a short consented usage example and choose next scope from evidence. |

Use the bug/feature issue forms and weekly triage. Track opt-in repeat usage,
configuration mistakes caught and confirmed bugs fixed manually. No telemetry.
Share a local demo in suitable communities under their rules; no bulk messages.

One planned release per month, with urgent correctness/privacy fixes when needed.
Keep dependencies minimal and require local gates plus three successful hosted
CI jobs before a release. npm publication is a separate future decision.
